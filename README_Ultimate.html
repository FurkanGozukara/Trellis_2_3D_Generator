Workflow Build Over Demo Surface

Trellis 2 Ultimate is the polished workflow layer on top of official TRELLIS.2.

This HTML README presents the verified differences between the official upstream app and the Ultimate package centered around app_premium.py. The model backbone stays official, but the user experience grows into a multi-tab production workflow with one-click style installers, precompiled heavy libraries, stronger export control, rigging, animation utilities, and offline-friendly model handling.

Important scope boundary

This comparison is about the end-user application, inference workflow, export pipeline, rigging and animation utilities, runtime behavior, installers, and offline model management. The official repo still includes research and training-oriented code that this package does not aim to replace.

In plain terms: Trellis 2 Ultimate is not a training-code superset of the official repo. It is a much larger inference and workflow package built around the official backend.

Premium App Surface

From one demo tab to a seven-tab workflow hub

The official upstream app is intentionally simple. Ultimate centers the experience around app_premium.py and turns TRELLIS into a broader day-to-day working environment instead of a single generate-and-download demo.

Image -> 3D

The main generation surface grows into a much wider workflow with more runtime controls, extraction tuning, progress feedback, and multi-image support.

Texturing

A dedicated texture workflow stays available inside the premium app instead of living as an isolated minimal demo.

UltraShape Refine

Existing meshes can be refined against reference images directly from their own tab or injected into the main export pipeline.

View 3D Files

The app also acts as a lightweight local model viewer for already-generated assets instead of assuming every session starts from scratch.

Help / Settings Guide

Ultimate includes in-app guidance so the user does not need to decode every advanced switch by trial and error.

Rigging

UniRig integration brings skeleton generation, skinning, merge/export, previews, and handoff into the animation browser.

Animation Player

Rigged outputs can be browsed, previewed, and driven with simple animation styles such as dance, walk, and idle.

Generation Upgrades

More input modes, more resolutions, more control over the model path

The official app gives a clean image-in demo. Ultimate exposes far more of the generation stack and adds entirely new ways to drive it, especially for users working with ordered view sets and tighter VRAM budgets.

Multi-angle input More resolutions Sampler selection Attention backend selection

Multi-image and multi-angle generation

  • Multiple uploaded images in one run.
  • Drag reordering for view control.
  • Primary-view aware handling.
  • Dedicated multi-view fusion modes: stochastic and multidiffusion.

Expanded resolution envelope

  • Official UI exposes 512, 1024, and 1536.
  • Ultimate adds 768, 1280, and 2048.
  • Users can also enter a custom resolution when it is divisible by 128.

Three pipeline strategies

  • reference_auto for the default high-quality path.
  • direct_1024 for a more direct 1024 route.
  • hybrid_512g_1024t for lower-memory geometry plus higher-res texturing.
Model and runtime selection

Ultimate surfaces standard and fp8 variants, attention backends such as auto, flash_attn, flash_attn_3, xformers, and sdpa, plus sampler choices heun, euler, rk4, and rk5.

VRAM-aware controls

Users get a low-VRAM mode, token budget control, force high-resolution conditioning, chunked triangle handling, and tiled extraction paths for both generation and final export stages.

Why this is a real upgrade

The official backend contains lower-level capability, but the official app does not expose most of it. Ultimate turns those deeper choices into usable workflow controls instead of leaving them buried in the stack.

Batch And Presets

A real repeatable workflow instead of one-off manual runs

Official TRELLIS.2 does not provide folder batch processing or a preset system. Ultimate adds both, which matters immediately for users generating many assets with stable settings.

Batch processing features

  • Folder input and optional custom output folder.
  • Supported image extension filtering.
  • Per-file seed handling.
  • ETA plus processed, skipped, and failed progress reporting.
  • Safe resume behavior by skipping images whose output folders already exist.
  • Optional preview skipping to save time and memory.

Preset system

  • Built-in best and low_vram presets.
  • Save current UI settings to custom presets under presets/.
  • Load, reset, and delete custom presets.
  • Remember the last-used preset.
  • Coverage across Image -> 3D, Texturing, UltraShape Refine, and Rigging.

Extraction And Export

Ultimate turns one GLB extract button into a configurable post-processing pipeline

The official app can extract one GLB. Ultimate builds a fuller cleanup, repair, re-texture, and export system around that same basic handoff point.

Remesh Repair Deferred re-texture Projection refine Multi-format export

Mesh cleanup controls

  • Remesh method selection.
  • Simplify method selection.
  • Repair method selection.
  • Hole-fill perimeter threshold and invisible-face pruning.
  • Merge-vertices distance.
  • Shade smooth toggle and angle.

Material and export controls

  • Force double-sided materials.
  • Basecolor-only material export.
  • Texture size control.
  • Skip-texture-generation mode.
  • Direct export to glb, gltf, obj, ply, and stl.

Conditionally supported backends

  • Remesh: dual_contouring, dual_contouring_vb, faithful_contouring.
  • Simplify: cumesh, meshlib, none.
  • Repair: disabled, cumesh, meshlib, pymeshfix.
Deferred final texture rebuild

Ultimate can first clean, remesh, or simplify the extracted mesh and then run a separate final TRELLIS texture pass on that cleaned geometry. This matters because the mesh users keep is often not the raw direct extract, and the final bake can align better after topology changes.

Projection texture refinement from known views

Ultimate adds trellis2/projection/texture_projection_multiview.py and exposes view-aware projection controls such as per-view azimuth, elevation, blend exponent, orthographic scale, and hole filling. That gives users a route to texture from known real views rather than only the TRELLIS texture latent.

Structured export metadata

Ultimate writes extract_artifacts.json and mesh_audit.json so users can inspect what was created, which output is final, whether re-texture or fallback occurred, and what the mesh statistics look like across stages.

Structured numbered run folders

Instead of loose temp-style outputs, runs are organized into folders such as outputs/0001/ with run.json, logs, intermediate assets, 08_final_exports/, and 09_retexture_work/.

Texturing Workflow

Texturing stays first-class instead of living as a small side demo

The official repo ships a lightweight app_texturing.py. Ultimate keeps the same general idea but folds it into the premium app with more operational control and better workflow affordances.

Integrated tab

Upload a mesh, upload a reference image, and texture inside the main application instead of switching to a separate minimal utility page.

More runtime control

Low-VRAM mode, attention backend selection, sampler choice, and guidance interval tuning are exposed to the user.

Better workflow handling

Logging visibility, cancel support, output-folder actions, and example assets make the texturing path feel like part of a real production tool.

UltraShape Integration

One of the largest functional additions in the entire package

Official TRELLIS.2 does not ship this refinement workflow. Ultimate adds ultrashape_integration.py, a dedicated tab, and optional UltraShape refinement inside the main extraction path.

Standalone and embedded workflows

  • Refine an uploaded existing mesh against a reference image.
  • Insert UltraShape refinement into the normal Image -> 3D export path.
  • Use conservative mode to reduce geometry drift.
  • Optionally re-texture with TRELLIS after UltraShape changes.

Controls exposed in the UI

  • Checkpoint, config, and dtype selection.
  • Low-VRAM mode and background removal for the reference image.
  • Diffusion steps, guidance scale, and octree resolution.
  • Chunk size, target face count, latent count, thresholds, and sampling controls.

Install requirement

  • UltraShape needs both models/UltraShape/ weights and the UltraShape-1.0/ source checkout.
  • The installer and model-resume script run ensure_ultrashape_source.py automatically.

UniRig integration Rig previews Animation browser Animated exports

  • Generate a skeleton.

  • Merge back with original mesh and materials.
  • Export as fbx, glb, or both.

Preview surfaces

  • Skeleton preview tab.

Animation Player tab

  • Import external rigged models.

View 3D Files utility tab

Ultimate also includes a lightweight local viewer for .glb, .gltf, .obj, .ply, and .stl, so users can inspect existing assets without rerunning generation.

Help and settings guidance inside the app

The package includes in-app help and settings guidance so the expanded surface is easier to learn without relying only on external documentation.

Runtime And CLI

The package adds stability engineering, process isolation, and headless usage

One of the biggest practical gains is not only new features, but better survival under real workloads. Ultimate adds runtime orchestration around memory, cancellation, backend selection, and local model reuse.

Subprocess stage processing

  • Fresh Python worker stages for zero leftover VRAM between stages.
  • Better protection against long-session CUDA memory fragmentation.
  • A real worker process to terminate during cancellation.
  • Cleaner recovery after failed heavy stages.

Safer cancellation and runtime switching

  • Two-step cancel confirmation and cancellation state tracking.
  • Subprocess termination for active worker stages.
  • Batch cancel handling when subprocess mode is off.
  • Attention backend availability detection and dense/sparse matching.
Offline-friendly local model loading

Ultimate adjusts the pipeline loader so it prefers a local mirror under models/ via TRELLIS_MODELS_DIR before reaching out to Hugging Face. That makes repeated runs, packaged installs, and persistent cloud volumes much easier to live with.

Dedicated CLI entrypoint

inference.py gives the package a scriptable path for one or more images, extract settings, remesh and simplify choices, and direct file export. That enables headless automation and pipeline integration beyond the web UI.

Install Experience

One-click style helpers and cloud setup scripts reduce the usual pain

The official TRELLIS.2 install story is Linux-first and compile-heavy. Ultimate packages a much more deployment-oriented experience for end users, especially on Windows.

Windows install or update Resume model downloads Start-app helper RunPod and Massed Compute

Windows_Install_or_Update.bat

  • Clones Trellis_2_3D_Generator and UniRig.
  • Creates a Python 3.11 virtual environment.
  • Installs uv and the app requirements.
  • Installs heavy wheel packages such as flex_gemm, o_voxel, and spconv.
  • Clones and installs FaithC.
  • Launches the downloader.

Windows_Model_Download_Resume.bat

  • Reruns the downloader without forcing a full restart.
  • Lets interrupted downloads continue instead of starting over.
  • Pairs with checksum verification for safer recovery.

Windows_Start_App.bat

  • Activates the virtual environment.
  • Sets useful runtime variables.
  • Points HF_HOME to the local models folder.
  • Starts app_premium.py directly.

Cloud and remote install scripts

  • RunPod_Install_Trellis.sh
  • Massed_Compute_Install.sh
  • Each creates a Python 3.11 venv, installs uv, installs requirements, installs wheel-based heavy CUDA packages, installs FaithC, and runs HF_model_downloader.py.
Why users feel this difference immediately

Ultimate does not only add features. It adds a more usable path to getting the environment running in the first place: Windows support, starter scripts, download resume, and dependency choices that avoid unnecessary local compilation where possible.

Precompiled Libraries

The package leans hard on wheel-based delivery for painful dependencies

This is one of the strongest practical improvements over the official setup path. Instead of forcing more users into local CUDA builds, Ultimate is designed around a precompiled dependency strategy wherever possible.

Attention and runtime acceleration

flash_attn xformers sageattention triton triton-windows

Geometry and sparse CUDA stack

nvdiffrast cumesh cumm torch_scatter torch_cluster cubvh atom3d

Packages installed explicitly by helper scripts

flex_gemm o_voxel spconv FaithC
Why this matters to real users

Fewer people need to compile large CUDA extensions themselves, Windows installs become more realistic, cloud instances come up faster, and the support burden drops because the dependency path is more standardized.

Downloader And Offline Model Store

Model management is treated like part of the product, not a side chore

HF_model_downloader.py is a meaningful upgrade on its own. It gives the package a resumable, verified, multi-connection model acquisition path and works directly with the local offline-friendly model layout.

Verified downloader behavior

  • Targets Trellis_2_3D_Generator/models.
  • Uses 16 connections.
  • Supports HTTP range resume when available.
  • Includes retry and backoff logic.
  • Verifies with SHA256 and caches verification state.

Bundles and coverage

  • TRELLIS model packs.
  • UltraShape bundle download.
  • DINOv2 bundle download.
  • Direct repo download paths.
  • BiRefNet download support and optional Hugging Face token usage.
Persistent verification state

The downloader writes sha256_cache.json and verified_files_cache.json, which is far better than treating every rerun as a blind full redownload.

Better offline reuse

Because the loader prefers local mirrors under models/<org>--<repo>/..., the completed model store can be reused across runs, kept on a persistent cloud volume, or shipped as part of a more offline-friendly setup.

Bottom Line

Official TRELLIS.2 is the research demo. Trellis 2 Ultimate is the workflow build.

The practical value of Ultimate is not one single feature. It is the way the package closes all the gaps that real users usually hit after the first successful generation: installation pain, VRAM instability, cleanup quality, export flexibility, repeatability, rigging, animation, and model-management friction.

What stays official

The TRELLIS.2 backbone remains the foundation for image-to-3D and texturing.

What Ultimate adds

Multi-angle fusion, batch runs, presets, deferred re-texturing, projection texture refine, UltraShape, UniRig, animation browsing, one-click style installers, and an easier precompiled dependency path.

What users feel first

Faster setup, more control, better survivability, cleaner outputs, and a wider workflow after generation instead of a dead-end demo screen.
